# vault-doctor · 笔记库结构体检 Agent

检查 Obsidian 笔记库的结构健康度，找出**掉队**和**断链**的笔记，并自动生成一张真实反映笔记关系的知识地图。

一次运行约 30 秒。

> **v2.0（2026-10-18）**：依赖关系改由代码从索引页表格抽取，模型不再逐页读索引去翻「前置」列。详见「十二、版本记录」。

---

## 一、它有什么用

如果你的笔记库是下面这样，它就有用：

| 你的情况 | 它能帮你做什么 |
|---|---|
| 笔记越来越多，索引页开始跟不上 | 列出**没被任何索引收录**的笔记 |
| 不确定有没有链接指向了不存在的笔记 | 扫出全部**断链** |
| 建了占位笔记，忘了往里写东西 | 找出**空文件** |
| 想看看自己的知识结构长什么样 | 生成一张 mermaid 知识地图，可直接在 Obsidian 里渲染 |
| 手工维护知识图太累、还老是忘 | 每次跑一遍，图就是最新的 |

**一句话：它替你抬头看一眼全局。**

> 它不替代你的笔记软件。它解决的是"**没有任何环节负责通读全库**"这件事——手工维护的索引页会漏，因为它只在你想起它的时候才更新。

---

## 二、它输出什么

### 产物文件

```
<你的笔记库>/_auto/C++ 知识地图.md
```

- 写入位置固定在笔记库下的 `_auto/` 子目录
- **不会修改、不会删除你任何现有笔记**
- 文件名可以改（见「七、参数」）

### 产物内容

固定三节，章节一个不多一个不少。

**① 结构体检** —— 用表格逐条列出发现的问题：

| 笔记 | 字数 | 应归入 | 理由 |
|---|---|---|---|
| `C++ Rule of Five 详解` | 0 字 | 🏗️ 类 | 三/五法则讲的五个特殊成员函数，是「构造函数与析构函数」的延伸 |
| `C++ 分层算法练习题` | 8131 字 | 顶层（与索引并列） | 跨主题综合练习，不属于任何单一分组 |

**② 知识地图** —— 一个 `mermaid graph TD` 代码块：

- **实线** = 笔记里已经存在的链接
- **虚线** = 模型建议新增的归属关系

**③ 建议** —— 三条以内，每条都指向具体笔记，不说空话。

### 终端输出

运行时会在终端打印完整执行轨迹，方便确认它到底干了什么：

```
第 1 轮：把 2 条消息发给模型
  → 调用 scan_vault  参数=无
  → 返回：笔记总数：21  【全部笔记】标题 | 字数 …

第 2 轮：把 4 条消息发给模型
  → 调用 read_note  参数=['filename']
  → 返回：《C++ 学习索引》全文：…

第 3 轮：把 10 条消息发给模型
  → 调用 write_report  参数=['filename', 'content']
  → 返回：已写入：E:\Obsidian\notes\_auto\C++ 知识地图.md……

第 4 轮：把 12 条消息发给模型
任务结束。
```

## 三、它是怎么判断的

| 检查项 | 判定规则 |
|---|---|
| **孤儿笔记** | 全库里没有任何笔记通过 `[[链接]]` 指向它 |
| **断链** | 笔记里的 `[[xxx]]` 指向的文件不存在 |
| **空文件** | `.md` 内容为空，或只有空白字符 |

> **注意**：孤儿 ≠ 没用。一篇笔记没被链接，可能只是你还没给它加入口。

## 五、配置

复制模板，再填自己的值：

```bash
cp config.example.py config.py         # Windows: copy config.example.py config.py
```

打开 `config.py`，填四处：

```python
API_KEY    = "sk-你的密钥"                # https://platform.deepseek.com 申请
BASE_URL   = "https://api.deepseek.com"   # 换别家模型改这里
MODEL      = "deepseek-chat"
VAULT_PATH = r"E:\Obsidian\notes"         # 你的笔记库根目录
```

> `VAULT_PATH` 填**笔记库根目录**——就是能看到 `.obsidian` 文件夹的那一层。
>
> `config.py` 已在 `.gitignore` 中排除，不会被提交。

## 六、使用

```bash
python vault_doctor.py
```

没有命令行参数。跑完去笔记库的 `_auto/` 目录看产物。

想换一个提问，改文件最后这行：

```python
run_agent("帮我做一次完整的笔记库结构体检，并生成一张真实的知识地图。")
```

## 九、常见问题

**`UnicodeEncodeError: 'ascii' codec can't encode characters in position 10-16`**

`config.py` 里的 API Key 还是占位符，没换成真的。报错里 `position 10-16` 指向的正是 `Bearer sk-在这里粘贴你的key` 这串字符中文字符的位置——数一下就能定位。

**`can't open file '...\vault_doctor.py': No such file or directory`**

当前目录不对。先切到项目目录再运行：

```bash
cd path/to/vault-doctor
python vault_doctor.py
```

**`ModuleNotFoundError: No module named 'config'`**

没建 `config.py`。见「五、配置」。

**跑出来笔记数是 0**

`VAULT_PATH` 填错了，或者指向的不是笔记库根目录。

**模型一直要工具、停不下来**

把 `max_rounds` 调小，或把 `PROMPT_MODE` 换成 `"strict"`。

## 十、安全说明

- **只读你的笔记**。全项目唯一的写入操作是往 `<笔记库>/_auto/` 写产物
- **不会修改或删除任何现有笔记**
- API Key 只存在本地 `config.py`，该文件已被 `.gitignore` 排除
- 模型只能通过三个工具接触你的文件：全库扫描、读单篇、写产物——**没有删除能力**

## 十一、它是怎么工作的

一个标准的 tool-calling 循环：

```
用户提问
   ↓
把消息 + 工具清单发给模型
   ↓
模型自主决定调用哪个工具（可能一次调好几个）
   ↓
本地执行工具，结果作为 role="tool" 的消息回灌
   ↓
模型拿着结果再决定一次 …… 直到它不再需要工具
   ↓
输出最终结果
```

**三个工具：**

| 工具 | 类型 | 作用 |
|---|---|---|
| `scan_vault()` | 确定性 | 全库扫描，返回结构快照 |
| `read_note(title)` | 确定性 | 读单篇笔记全文 |
| `write_report(name, content)` | 有副作用 | 写入产物（限定在 `_auto/` 目录内） |

---

### scan_vault() 返回什么

`scan_vault()` 是模型看世界的入口——它把整个笔记库压成一份文本快照。包含六段：

| 段落 | 内容 |
|---|---|
| 笔记总数 | 一句话 |
| 【全部笔记】 | 每篇的标题 + 字数 |
| 【出链关系】 | 谁 `[[链接]]` 到了谁 |
| **【依赖关系】** | **哪篇笔记的前置是谁** ← v2 新增 |
| 【孤儿笔记】 | 没有任何笔记链接到它 |
| 【断链】 | 链接指向了不存在的笔记 |
| 【空文件】 | 内容为空的 `.md` |

**【依赖关系】长这样：**

```
【依赖关系】哪篇笔记的前置是谁
- C++ 构造函数与析构函数  前置 = C++ 类完全指南
- C++ 字符串完全指南      前置 = C++ 类完全指南, C++ 运算符重载
- C++ 虚函数              前置 = C++ 继承
```

**它消除了一处具体的浪费**：在 v1 里，这个信息只写在索引页的表格里，模型必须调用 `read_note` 把那几张表读一遍才拿得到。v2 用 `extract_deps()` 把它抽出来，模型一次都不用读索引页了。

> **抽法**：只看**表格行**——第一格是 `[[笔记名]]`，最后一格是它的前置。
> 表头行、分隔行、其他对比表因为第一格没有 `[[ ]]`，会被自然排除。
> **所以不需要预先判断"哪个文件是索引页"**：判定粒度在「行」，不在「文件」。

## 十二、版本记录

### v2.0 · 2026-10-18

**改了什么**：把「笔记之间的前置关系」从"让模型去读索引页"改成"由代码直接从表格里抽"。

- 新增 `extract_deps()`，`scan_vault()` 的返回结果多出【依赖关系】一节（本库抽出 10 条）
- 启动日志加 `[v2]` 前缀，便于和 v1 区分
- 其余逻辑（出链、孤儿、断链、循环、两版 prompt）与 v1 完全一致

**实测对比（同一任务、同一 prompt）：**

| | v1 | v2 |
|---|---|---|
| 总轮数 | 4 | 6 |
| 消息数峰值 | 12 | 20 |
| 读索引页次数 | 5 | **0** |
| `read_note` 次数 | 5 | 6（改为读个别笔记） |

**结果不算漂亮，但值得记下来**：读索引页这一步确实消除了，**总成本却上升了**。

原因是原料变全之后，模型转向去验证依赖链上的关键节点（`类完全指南`、`继承`、`栈与堆`、`const 指针`），以及读那两篇孤儿笔记来判断归属——**它没有偷懒，它做了更多的事**。

**由此得到一条原则**：想让 Agent 省钱，光"给更好的原料"没用，还得明确告诉它"到这儿就够了"。

**下一步**：在 system prompt 里加一句"结构信息已在扫描结果中，无需逐篇读取"，把成本压回去。

### v1.0 · 2026-10-15

首个可用版本：全库扫描、孤儿/断链/空文件体检、生成 mermaid 知识地图。

### 两个文件的关系

`vault_doctor.py` 是 v1，`vault_doctor_v2.py` 是 v2。两者并存，方便对照运行。

# 附录：开发笔记（选读）

> 以下内容与"怎么用这个工具"无关，记录的是开发过程中的两个设计决定、一个对照实验和已知局限。只看使用说明的话，到上一节就可以结束了。

## A. 两个设计决定

### 代码做确定的事，模型做需要判断的事

工具不是越多越好，而是要把职责切开：

| 交给代码（确定性） | 交给模型（语义判断） |
|---|---|
| 遍历目录、解析双链、数字数 | 这篇孤儿笔记该归到哪个分组 |
| 统计孤儿和断链 | 两篇笔记谁是前置 |
| 拼装 mermaid 语法 | 「Rule of Five」和「构造函数与析构函数」是什么关系 |

**脚本会数数，但脚本不认识 `Rule of Five` 是那五个特殊成员函数。** 这条边界划在哪，决定了 Agent 是聪明还是笨。

### 锁死"输出格式"，不锁死"步骤"

- **格式要锁死**——产物必须是「结构体检 / 知识地图 / 建议」三节，否则每次跑出来结构都不一样，没法用。
- **步骤不要锁**——一旦规定"先做 A 再做 B"，模型会连表达一起变保守。

**约束该加在"要什么"上，不该加在"怎么做"上。**

## B. 一个对照实验：约束强度 vs 输出质量

任务、工具、输出结构、铁律全部相同，只改 system prompt 的约束强度，各跑一次。

|  | `PROMPT_STRICT` | `PROMPT_LOOSE` |
|---|---|---|
| 步骤 | 明确列出 3 步 | 不写，让模型自己决定 |
| 线索 | 告诉它依赖关系在索引页表格里 | 不给 |
| 语气 | "工作流程是固定的，不要自由发挥" | 无 |

**数据：**

| 观察点 | 限定步骤版 | 只给目标版 |
|---|---|---|
| 第 1 轮 | `scan_vault` | `scan_vault` |
| 消息条数轨迹 | 2 → 4 → 10 → 12 | 2 → 4 → 10 → 12 |
| 第 2 轮读了几篇 | 5 篇（一轮并列） | 5 篇（一轮并列） |
| 总轮数 | 4 | 4 |

**结论：过程零差异，差异只在表达。**

输出侧的差别：限定版用嵌套小圆点，只给目标版换成了四列表格；限定版没有收尾观察，只给目标版主动补了一段；同一篇笔记的归类判断也更准。

**推断**：那句"不要自由发挥"本意只管**步骤**，但副作用**溢出**了——连**表达**一起压住。过程之所以纹丝不动，是因为**工具自身的 `description` 里还拽着引导**（`scan_vault` 写着"必须先调用它"）。

**两条启示：**

1. 一句约束的副作用，会溢出到它没打算管的地方。
2. 提示词无法真正"清空"引导——每一个 `description` 都在下指令。

> ⚠️ 样本量：n=1 vs n=1。方向明确，但**还没做多次重复验证**。

## C. 已知局限

- `scan_vault()` 把全库结构一次性塞给模型，笔记规模再大就会超出上下文。**解法应是分级检索**（先给目录，让模型按需深入）。
- 双链解析用的是正则，没有处理 `![[嵌入]]`、`[[链接|别名]]`、`^blockid` 等 Obsidian 高级语法。
- 写入位置硬编码在 `_auto/`，是安全考虑，但不够灵活。
- 只处理单库，不支持多 vault。

## D. 关于这份代码

这是一个边学边写的小项目，代码有大量 AI 辅助。但每一行都读过、跑过，也知道它为什么这么写。

## E. 学到什么

- **模型没有记忆。** 每一轮都要把完整对话重新发过去。它"记得什么"，完全取决于你塞回去了什么。
- **`description` 不是注释。** 注释是给人看的，`description` 是写给**模型**看的接口说明。
- **模型可以"边说边举手"。** 调用工具时 `content` 字段往往不是空的，只处理 `tool_calls` 会丢掉它的思考过程。
- **错误信息也是写给模型的。** 工具失败时返回一句"未知工具：xxx"而不是抛异常，模型看到会自己改对。
